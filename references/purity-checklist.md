# Purity Checklist

审计用 checklist — 检查代码或文档是否读起来像"第一次写的"。Purity principle 要求所有代码和文档无溯源残留、无装饰、无死指令、无 doc/impl 裂隙。本文件是审计工具,与 [engineering-principles.md](engineering-principles.md)(行为纪律)互补:principles 管"怎么工作",本文件管"查什么残留"。适用于任何源文件——代码、技能文档、README、reference。

每类给**查什么** + **怎么查**(可操作检查法)。

---

## A. 溯源残留

文件里带着"这是何时/为何加的"叙事——版本、日期、task ID、"本次改动"指针。读者不需要知道历史,只需当前事实。

1. **标签式溯源** — 小节标题/括号带版本或事件:`（v2.8 新增）`、`（XX 事件）`、`（已观测）`、`（保留）`。怎么查:grep `（.*新` / `（.*保留` / `（.*事件` / `（.*已观测`。
2. **正文嵌版本号/变更指针** — "自 vX 起…"、"详见 CHANGELOG"、"之前是 X,现改为 Y"、"原来用的是 A,现已迁移到 B"。怎么查:grep `v[0-9]\.[0-9]` 出现在正文(非 frontmatter/徽章/依赖声明);任何"之前/原来/改为/迁移到/升级后"句式。规则:正文只陈述当前事实;版本演进归 git log / release notes / CHANGELOG。
3. **分组按批次而非维度** — 比 #1 隐蔽:不是文字标签带溯源,是**信息架构本身带时间线**。分组按"加入顺序"(基线 / 原有 / 某次新增批次)组织,而非按主题维度。怎么查:**把所有小节标题的溯源词删掉后,分组是否还合理?** 不合理 → 分组本身是残留,按维度重组。

## B. 装饰与冗余

为达标而存在、不承载信息的结构。

4. **装饰性 diagram / 注释** — 为凑"≥N 张图"或"每个函数有注释"而画/写、不服务信息。怎么查:**删掉它,读者会少理解什么?** 答案是"nothing" → 装饰,删。每张图/每条注释须承载路由/决策/时序/结构/why 信息。
5. **benchmark 角标 / 名次当卖点** — 文档里 `#N 排名`、stars 数、benchmark 分数当推荐理由。怎么查:角标是否驱动当前决策?若只是"看它多流行",降为背景或删。
6. **重复/冗余** — 同一内容多处陈述(规则在 principles 又在 skill 又在 ref)。怎么查:同一断言 grep 命中 ≥2 处,确认是否一处链另一处而非复制。
7. **特例 guard** — 用 bolded 特例补丁架构字段("**除非** X 才 Y"、`// 注意:这里要特殊处理 Z`),而非把 X/Z 纳入字段定义或数据结构。怎么查:找 `**除非**` / `**注意**` / `**例外**` / `// 特殊` / `// HACK`,判断能否重构为架构字段而非补丁。

## C. 死内容

文件声称存在、但实际没有/已过时的东西。

8. **死指令** — "统一/一律/必须"类规则,正文实际未全做到。怎么查:**每条"统一/一律/必须/全部"指令,抽验正文是否真的全做到。** 例:开头声明"所有示例统一用 TS",但正文混入 JS → 死指令。
9. **死链接/过时引用** — `](x.md)` 指向不存在文件;引用的符号/函数/flag/类名已改名或删除。怎么查:validator 或 lint 查死链;人工查引用的 file:line / 函数名 / flag / API 是否仍存在。
10. **死字段/死参数** — frontmatter、配置表、函数签名的字段/参数无人读、无消费者。怎么查:字段值是否被某逻辑消费?grep 字段名全仓无读取 → 删。

## D. doc/impl 裂隙

文档声称与实际结构/行为不符——purity principle Rule 4(部署生命周期一致)。代码侧是注释/接口文档与实现不符;文档侧是规范与产物不符。

11. **校验项与动作不对应** — 文档/测试的检查项写了"检查 X"但实现无产生 X 的动作;或代码做了 Y 但校验没查。技能包特例:Verify 写了检查但 Steps 无对应动作。怎么查:**逐条校验项反查有无对应动作源;逐条动作反查有无校验。**
12. **产物路径 ↔ 矩阵/清单不同步** — 文档声明的产物路径与实际产物清单不一致。技能包特例:SKILL.md 的 `**Output:**` 与 `docs/skill-outputs.md` 矩阵不一致。怎么查:改声明时同步改清单;validator / lint 查。
13. **跨实例共享结构 drift** — 多处共享同一结构(如多模式共享 spine、多模块共享接口契约),但某实例偷偷改了命名或顺序。怎么查:grep 共享结构的标题/字段名,确认所有实例用词一致。
14. **章节/编号跳号** — 1,2,3,5,6(漏 4)或编号复用旧号、API 参数序号断。怎么查:编号是否连续无跳;validator/lint 多不查,人工查。

## E. 语言与平台残留

夹带不属于当前语境的内容。

15. **语言混用** — 一种语言文档夹另一种语言叙述(代码标识符/枚举值/专有名词除外)。怎么查:正文语言是否一致;标识符保留原文是允许的,叙述性句子不该混语言。
16. **平台/工具实现痕迹** — 特定平台/工具的实现细节(某 MCP server 的命令名、某框架的私有 API、某 CI 的 step id)混进通用规则。怎么查:规则是否平台无关?实现细节归实现处,不进通用 ref / 通用接口。

---

## 审计流程

1. **先 grep 后人工** — A/B/C 类多用 grep 批量发现(版本号、溯源词、死链接、重复断言、`// HACK`);D/E 类需人工逐项对照。
2. **按维度重组,不只删标签** — A 类 #3(批次分组)是结构残留,删标签不够,要重组。
3. **删完跑 validator / lint / 测试** — 自动化查死链 + 产物同步 + 结构;但查不了死指令/装饰图/校验-动作对应,这些靠人工。
4. **改完即提交,不留"待清理"** — purity 违规是当前债,不留 TODO("下次清理 X")——那本身又是溯源残留。
